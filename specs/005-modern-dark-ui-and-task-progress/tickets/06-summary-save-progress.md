# 06 · 总结、后处理、保存流程进度埋点

- **依赖**：01、02
- **关联**：spec §5
- **状态**：已完成

## 目标

覆盖 GPT 总结之后的内容后处理、数据库保存和终态写入，避免前端长期停留在一个模糊的“总结中”。

## 改动点

1. 总结阶段显示请求开始、checkpoint/续写信息和完成状态；不可估算时使用活动状态。
2. 增加 `post_processing`，覆盖截图和视频链接替换。
3. `saving` 阶段区分结果文件、数据库和状态文件保存。
4. 成功和失败携带最后阶段及可读消息。
5. 保持现有 checkpoint 和缓存恢复逻辑。

## 验收

- 总结完成后不会直接从 `SUMMARIZING` 跳到 `SUCCESS` 而跳过可观察后处理。
- 保存失败能准确显示处于保存阶段。
- 旧缓存命中路径仍能完成任务。
