# 09 · 暗色设计 token 与基础组件统一

- **依赖**：无
- **关联**：spec §4、§7
- **状态**：已被取代（2026-10-05）

## 为什么被取代

本工单的全部内容建立在 spec 005 §4 决策 7/8 之上 ——「仅暗色主题」「以 `#780018`/`#AA0033`/
`#CC0044`/`#2B2B2B`/`#4A4A4A`/`#1A1A1A`/`#6B6B6B` 为基准」。

**用户于 m02324 明确：浅色 DesignMD 才是最终意图。** 因此「暗色紫红主题」不再是一个待实现的目标，
本工单整体作废，工单 10/11 中与主题相关的部分同步失效。

## 这条决定实际解释了哪些现象

下面这些**曾经被记为缺陷、现在不再算缺陷**：

- `BillNote_frontend/src/index.css:209–275` 的 `:root` 块用 `!important` 覆盖了紫红 token —— 那是浅色方向，
  不是「旧主题冲突样式残留」。
- `#6B6B6B` 只作为 `index.css:169` 的字面量出现、从未成为 token —— 浅色方向不需要它。
- `src/components/ui/` 下 17 个组件的 `dark:` 变体永不激活 —— 浅色方向不需要它们激活。
- 焦点环用 `#3B82F6` 而不是品牌紫红 —— 浅色方向下这是正确的。

## 仍然残留的一处（已归入工单 12）

`BillNote_frontend/src/pages/HomePage/components/StepBar.tsx` 已无任何引用，是死代码。
它与主题无关，所以没有随本工单一起作废。
