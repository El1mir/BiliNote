# 16 · 进度停滞可见性（耗时与最后更新时间）

- **依赖**：07、08（时间线组件）
- **关联**：spec §7、§4 决策 4
- **状态**：已完成
- **日期**：2026-09-26（实机排查 99% 卡住时提出）

## 背景

`ProgressTimeline.tsx` 已经展示阶段、全局进度、阶段进度和 `updated_at` 时刻，
但用户看不出「这个进度是不是已经停了」：99%（`saving`）本来就是一个**长时间不动的合法状态**，
而真正卡死时界面也没有任何提示。实机排查中用户能提供的唯一线索就是「卡在 99」。

## 改动点

1. 时间线头部显示任务耗时（`createdAt` → 至今，终态则显示总耗时）。
2. 显示「最后更新 X 前」的**相对时间**（每秒刷新），而不是只有一个绝对时刻。
3. 非终态且 `updated_at` 超过阈值（建议 60s，可常量集中定义）时，
   显示「后端仍在处理，超过 X 无状态更新」的弱提示，并保留活动指示器（不伪造百分比）。
4. 终态（`SUCCESS`/`FAILED`）或页面不可见时停止计时器，避免无意义重渲染。
5. 纯展示层改动：不改后端协议、不改轮询间隔。

## 验收

- 长阶段（如 `summarizing`）能明确看到「最后更新 2 分钟前」。
- 停滞超过阈值出现提示，恢复更新后提示自动消失。
- 窄屏不溢出；`pnpm build`、`pnpm lint` 通过。
