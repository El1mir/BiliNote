# 006 · 笔记生成流水线耗时优化（并发与冗余消除）

- **状态**：implemented
- **日期**：2026-09-26
- **范围**：后端生成流水线的并发化、冗余网络请求消除、任务关键路径瘦身
- **上游**：001 / 002 / 003 / 005

## 1. 背景

2026-09-26 实测一次真实任务（BV1E7wtzaEdq，含视频理解）的耗时分布：

| 阶段 | 实测 | 现象 |
|---|---|---|
| 音频转写 | 138.69s | 80 个语音片段**串行**逐段请求 ASR（`openai_asr.py:256-282`）；限流 60 次/分钟根本没吃满 |
| 拼图 + base64 | 数分钟 | `video_reader.py` 45 组网格**串行**拼接，400 帧**串行**读文件 + base64，且全程无进度回报 |
| 截图 | 每个标记一次 ffmpeg | `_insert_screenshots()` 串行 `subprocess.run` |
| 视频 + 音频下载 | 两次 yt-dlp 网络下载 | 已经下载了视频，仍为取音频再下一遍网络 |
| 向量索引 | 2s+ | 在 `SUCCESS` 之后**占用任务工作线程**同步执行 |

其中转写、拼图、base64、截图都是**纯 IO/CPU 等待**，机器有多个核却只有一个在工作；
两次下载与重复字幕请求则是可消除的冗余。用户在前台等待整条流水线，这些时间直接变成等待。

## 2. 目标

1. 在不改变输出内容（字幕文本、帧选择、网格图、笔记 Markdown）的前提下压缩端到端耗时。
2. 并发度可配置、可回退：任何新增并发都有开关与串行兜底路径。
3. 消除已知冗余网络请求：同一任务的重复平台字幕请求、已下载视频后的二次音频下载。
4. 不让与任务结果无关的工作（向量索引）占用任务执行线程。
5. 顺带补上长时间静默环节的进度回报（拼图 / 编码 / 截图）。

## 3. 非目标

- 不改动采样算法、LLM 提示词、转写质量参数与网格尺寸语义。
- 不改动任务状态协议字段（沿用 spec 005 §5）。
- 不引入新的第三方依赖（只用标准库 `concurrent.futures`）。
- 不为了并发牺牲限流：ASR 并发请求仍受「每分钟请求数」约束。

## 4. 已定决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | ASR 并发粒度 | 按「切片/分段」并发，默认 `chunk_concurrency=4`，范围 1–32，可在 ASR 端点配置里改 |
| 2 | 限流关系 | 并发只用来填满已经配置的每分钟请求数，不提高 `max_rpm`；`_RateLimiter` 已是线程安全实现，直接复用 |
| 3 | 结果顺序 | 所有并发环节必须保持输入顺序（分段顺序即时间轴顺序），用 `executor.map` 保序 |
| 4 | 失败语义 | 并发体中单个失败等价于原串行失败：抛出即整段失败并走原有错误处理/任务重试 |
| 5 | 进度回报 | 并发任务用线程安全计数器累加完成数，`stage_progress = 已完成 / 总数` |
| 6 | 进度单调性 | 拼图与 base64 编码合并为同一个 `building_grids` 阶段的分母（网格数 + 图像数），避免阶段回退导致进度倒退 |
| 7 | 下载冗余 | 需要视频的场景复用已下载视频本地抽音频；已有平台字幕时不再下载音频（补 `skip_download` 支持） |
| 8 | 重复字幕请求 | `generate()` 已试过平台字幕时，`_get_transcript()` 不再重试一次（避免重复 API + yt-dlp 回退） |
| 9 | 向量索引 | 改为独立后台线程池执行，失败仅告警，不影响任务终态 |
| 10 | 并发线程数上限 | 取 `min(配置并发, cpu_count)`，避免小机器上过度切换 |

## 5. 接口与配置

- ASR 端点新增字段 `chunk_concurrency`（int，默认 4，1–32）。
  - 配置落盘：`config/transcriber.json` → `openai_asr_endpoints[].chunk_concurrency`
  - 环境变量兜底：`OPENAI_ASR_CHUNK_CONCURRENCY`
  - 后端接口：`/api/openai_asr`（新增/更新端点）与 `/api/openai_asr/{id}/test` 透传
  - 前端：设置 → 音频转写配置 → 端点表单「并发请求数」
- 其它并发度（拼图、编码、截图）先取 `min(8, cpu_count)`，不暴露配置，避免设置项膨胀。

## 6. 测试与验收

- 并发路径与串行路径产出**完全一致**的结果顺序与内容。
- 单段失败在并发下仍抛出并触发原有失败处理。
- 有限流配置时，并发请求不会超过 `max_rpm`。
- `skip_download=True` 的下载器不再发起媒体下载请求。
- 已下载视频时不再发起音频网络下载（用本地抽音频）。
- 任务成功后向量索引在后台完成；索引失败不影响任务 `SUCCESS`。
- 功能验证：006 测试套件与全量后端回归均通过；真实视频基准耗时尚未在本次会话中重新采集。
