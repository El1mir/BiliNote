# 01 · ZIP 笔记归档与资源路径改写

- **依赖**：—
- **关联**：spec §4 决策 1–3、10；§6
- **状态**：实现已落地；验收测试待用户授权

## 目标

将当前浏览器端 `.md` 直出改为可离线查看的 ZIP 笔记包，包含笔记正文和实际引用的本地截图。

## 改动点

1. 后端增加按 `task_id` 导出归档的 API，返回安全命名的 ZIP。
2. 解析 Markdown 图片语法，提取本地静态资源引用；仅解析/读取配置的截图根目录内文件，防止路径穿越。
3. ZIP 写入 `note.md` 与 `assets/`；对包内 Markdown 的本地资源 URL 改写成相对路径，远程 URL 保持不变。
4. 同名资源采用确定性重命名；缺失图片返回可见错误或告警，不悄悄生成缺图包。
5. 前端下载按钮调用 API 并保存 `.zip`；明确保留还是移除独立 Markdown 下载入口。
6. 响应关闭、失败和取消时清理临时文件；限制归档总大小/文件数并防止 ZIP Slip。
7. 确定桌面端、Web 端和浏览器扩展的支持范围；不在本 ticket 内改扩展时记录原因。

## 验收

- 本地截图在解压后可通过 `assets/` 相对路径显示，远程图片链接未被改写。
- 路径穿越、非法标题、同名图片、缺失文件和大归档边界均有测试。
- API/前端下载正确处理错误响应与文件名。

## 实现说明

- 桌面/Web 前端使用 ZIP API；浏览器扩展不在本次支持范围内，因为扩展独立维护下载流程，需单独发布与回归。
- 有限测试待后端获准运行后补齐；当前仅有静态语法检查和前端验证。
