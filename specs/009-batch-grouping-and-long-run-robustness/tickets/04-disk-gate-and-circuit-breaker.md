# 04 · 磁盘门禁与连续失败熔断

- **依赖**：02
- **关联**：spec §4 决策 11–12、§5、§6
- **状态**：已完成

## 目标

磁盘真不够时拒绝新任务，而不是跑到一半以 IO 错误失败；系统性故障不会让 200 个任务各重跑 4 遍完整流水线。

## 背景

`shutil.disk_usage` 全仓库零命中 —— 目前没有任何「整盘剩余空间」的观测或门禁。重试策略 `NOTE_MAX_RETRIES = 3` + `NOTE_RETRY_BACKOFF = [5, 15, 45]`（`backend/app/routers/note.py:126-128`、`:340-368`）每次重试**重跑整条流水线**（重下载、重转写、重总结），系统性故障（cookie 失效、供应商宕机、413）会命中全部 200 个任务，成本 ×4。

## 改动点

1. 磁盘门禁：
   - 新增基于 `shutil.disk_usage` 的检查函数，阈值读通用设置 `min_free_disk_bytes`（默认 5 GiB，见 ticket 07）。
   - `POST /api/generate_notes` 与 `POST /api/generate_note` 在入队前检查；不足则返回明确错误码 + 可读提示（沿用 `R.error(code=...)` 约定）。
   - 检查对象是媒体落盘所在盘（`get_data_dir()` / `OUT_DIR` 所在卷）。
   - 读取设置失败时**不**拦截（fail-open），避免设置读不到就把生成功能锁死 —— 与 `general_settings_dao.get_general_settings` 的既有容错方向一致。
2. 连续失败熔断：
   - 维护一个进程级「连续失败计数」+「同批暂停」状态；
   - 单任务仍重试 3 次（不改现有重试语义）；
   - 某任务最终 FAILED 时计数 +1，SUCCESS 时归零；
   - 计数达到阈值（默认 5）时，**暂停后续尚未开始的任务**（已入队但未执行的要能被跳过），并记录明确日志与状态 message；
   - 用户重新提交或显式恢复后计数归零；
   - 熔断阈值与开关放在通用设置（见 ticket 07）。
3. 熔断必须与 ticket 02 的调度器协同：暂停时不得留下永久占用的闸门名额。

## 验收

- 磁盘剩余低于阈值 → 新的生成提交被拒绝并给出可读提示；读写设置失败时不拦截。
- 连续 N 个任务失败 → 剩余未开始的任务被暂停，而不是继续各跑 4 遍。
- 成功一个任务后连续失败计数归零。
- 暂停不会泄漏闸门名额。

## 测试

- `test_disk_gate.py`：monkeypatch `shutil.disk_usage` 返回低剩余 → 断言 `/generate_notes` 与 `/generate_note` 被拒绝；设置读失败 → 放行。
- `test_circuit_breaker.py`：连续 N 次失败后断言后续任务被跳过；中间插一次成功则计数归零。
