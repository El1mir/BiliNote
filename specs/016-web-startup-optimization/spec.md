# 016 · 网页端单窗口启动与冷启动优化

- **状态**：approved（2026-10-15）

## 背景

根目录 run.bat 原先分别用 start ... powershell 创建后端、前端窗口，浏览器还会在服务就绪前打开。该脚本也会强制终止监听 8483/3015 的任意进程。实测后端就绪约 9.1s；import main 约 5.6–6.3s。前端 Vite 自身报告 ready 约 0.8s，npm 启动到 HTTP 可用约 2.27s。

导入分析显示 app/**init**.py 会导入所有路由；聊天路由在模块导入时加载 chat_service 与 vector_store，进而触发 ChromaDB/OpenTelemetry 的导入开销，即使本次启动不使用聊天/RAG。

## 目标

- 双击网页端启动脚本只使用一个控制台窗口，并在前后端都可访问后再打开网页。
- 保持前后端并行启动、控制台可查看日志、Ctrl+C 时仅停止本次启动器创建的子进程。
- 将聊天/RAG 重型依赖推迟到对应处理函数被调用时加载，且保持端点行为。
- 对占用端口的非本应用程序进程报告 PID，不静默杀进程。

## 非目标

- 本次不重构所有路由的加载方式，不加新依赖，不改生产部署架构。
- 不承诺 Vite 本身能显著快于当前约 0.8s；优化目标是减少包装器开销并避免过早打开浏览器。

## 已定决策

1. run.bat 在现有控制台同步执行一个 PowerShell launcher，不使用 start 创建服务窗口。
2. launcher 用直接 Node Vite entrypoint 与后端 Python 同时启动；探测 /api/sys_check 和前端根页成功后才打开浏览器。
3. 启动器只管理本次所创建进程；不通过端口号强杀任意外部进程。
4. 聊天路由只保留轻量的请求类型和路由注册；首次调用相关 handler 时再导入 ChromaDB 相关模块。

## 验收

- 可从 run.bat 路径触发无浏览器 smoke test，两个端点均 ready 后退出且清理本次服务进程。
- import 回归测试验证仅导入聊天路由不会把 chromadb 加载进 sys.modules。
- 在当前环境，import main 与启动 smoke test 相较改动前更快；记录环境相关耗时而不设跨机器硬阈值。
- 后端 016 测试、全量后端测试通过；相关诊断没有本次新增问题。
